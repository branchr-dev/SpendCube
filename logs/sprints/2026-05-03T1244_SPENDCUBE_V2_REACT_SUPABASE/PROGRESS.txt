- supabase/README.md — deployment instructions

**Schema summary:**
- 7 tables: engagements, pipeline_jobs, transactions (45 cols + engagement_id), supplier_master, supplier_match_log, category_overrides, audit_log
- 6 indexes on transactions and pipeline_jobs for engagement-scoped queries
- 5 views: v_by_supplier, v_by_category, v_by_month, v_by_bu, v_by_payment_terms
- RLS enabled on all 7 tables with SELECT/INSERT/UPDATE/DELETE policies scoped to auth.jwt()->>'email'

**Learnings:**
- invoice_date is stored as TEXT; v_by_month casts ::date — this is intentional and matches the v1 pattern. Will require valid date strings in the source data.
- RLS policy on engagements uses owner_email = auth.jwt()->>'email' directly; all other tables subquery engagements for the same check.
- Policy names (select_own_engagement etc.) are consistent across all tables for readability; Postgres scopes policy names per-table so there is no conflict.

## US-005 — Ingestion API endpoints — file upload, column mapping, and async pipeline execution
**Status:** COMPLETE (2026-05-03)

**What was created:**
- backend/app/routers/ingestion.py — APIRouter prefix=/api/engagements/{engagement_id}/ingest, tags=['ingestion']
  - POST /upload — validates .csv/.xlsx; saves to /tmp/spendcube_{uuid}.{ext}; reads nrows=1 for headers; returns {job_id, file_path, columns, row_count_estimate}
  - POST /run — validates engagement ownership; INSERTs pipeline_jobs row with status='queued'; calls background_tasks.add_task(_run_pipeline); returns {job_id, status: 'queued'}
  - GET /status/{job_id} — SELECTs pipeline_jobs WHERE id AND engagement_id; 404 if not found
  - _run_pipeline() — chains Ingestor → SupplierHarmoniser → SpendCategoriser → run_cube_pipeline with stage updates; handles exceptions → status='failed'
- backend/app/main.py — updated: imports ingestion router; registers router; adds @app.on_event("startup") to reset stuck jobs (status='running' → 'failed')
- backend/tests/test_ingestion_api.py — 5 tests covering all acceptance criteria

**Verified:**
- pytest backend/tests/test_ingestion_api.py -v → 5 passed in 0.31s
- pytest backend/tests/ -v → 10 passed (all prior tests still green)

**Learnings:**
- sys.path.insert at module level in ingestion.py (as specified in AC) works alongside the existing sys.path manipulation in app/database.py; no conflict
- column_mapping is applied as a pandas rename AFTER ingest_file() — safe because ingest_file auto-maps standard column names via DEFAULT source system, and column_mapping handles any non-standard names
- SpendCubePipeline (run_pipeline function) uses output_dir for Parquet; pass tempfile.TemporaryDirectory() to avoid writing to production paths
- on_event("startup") is deprecated in newer FastAPI; harmless DeprecationWarning in tests but functional
- Mocking app.routers.ingestion._run_pipeline in POST /run test prevents actual pipeline execution in TestClient

## US-006 — Cube data query endpoints — all five dimensional views plus overview and diagnostics
**Status:** COMPLETE (2026-05-03)

**What was created:**
- backend/app/routers/cube.py — APIRouter prefix=/api/engagements/{engagement_id}/cube, tags=['cube']
  - GET /overview — total_spend, invoice_count, supplier_count, category_count, currency_label, maverick_spend_pct, tail_spend_pct, data_freshness; queries transactions table directly; tail_spend_pct computed via cumulative spend algorithm (matching v1 SpendCubeBuilder logic)
  - GET /by-supplier — dynamic WHERE clause with category_l1, bu, date_from, date_to, supplier_search filters; sort_by allowlisted; returns {data: list, total_count}
  - GET /by-category — optional l1, date_from, date_to filters; returns flat list sorted by total_spend DESC
  - GET /by-month — SUBSTR(invoice_date, 1, 7) grouping; rolling_3m_avg computed in Python via pandas rolling(3).mean(); NaN → None
  - GET /by-payment-terms — bucket CASE expression; wc_opportunity_aud = max(0, (target_days - midpoint) / 365 * spend * wacc); uses config values with 45/0.08 fallbacks
  - GET /by-bu — business_unit + cost_centre grouping; ordered by total_spend DESC
  - GET /diagnostics — loads transactions via get_transactions(); instantiates DataQualityDiagnostics(df, config); returns run_all() dict
- backend/app/main.py — cube router imported and registered
- backend/tests/test_cube_api.py — 9 tests covering all acceptance criteria

**Verified:**
- pytest backend/tests/test_cube_api.py -v → 9 passed in 0.48s
- pytest backend/tests/ -v → 19 passed (no regressions)

**Learnings:**
- DataQualityDiagnostics takes (transactions_df, config), NOT (engine, engagement_id) as the acceptance criteria stated — must load transactions from DB first then pass DataFrame
- Queries target transactions table directly rather than Postgres views for flexibility with date/category/bu filters (views lack these columns)
- tail_spend_pct uses cumulative spend share algorithm (shifted cumsum >= 80% of total → tail), matching the v1 SpendCubeBuilder._add_tail_spend_flag() logic exactly
- SUBSTR(invoice_date, 1, 7) for month grouping is more portable than DATE_TRUNC since invoice_date is stored as TEXT
- Patching verify_engagement_ownership as AsyncMock(return_value=_MOCK_ENGAGEMENT) is the cleanest way to bypass auth in cube endpoint tests without touching the engine
